Programming How a Game Moves and Responds

In MS Pain, players can control either the main character or its shadow. Taking control of the shadow uses one available character switch. My contributions included items that restore these switches, enemy patrol work, moving platforms and testing shortcuts.

This page shows two examples: platforms that move on a repeatable cycle, and an item that restores one character switch when the player touches it.

2. Letting the player control the shadow again

The game idea: The main character and its shadow are two things the player can control. The character does not turn into a shadow. Instead, the player chooses which one to move.

Main character
You control the character.
Its shadow
You can choose to control the shadow instead.

Simplified illustration of the game concept. Taking control of the shadow is a limited-use ability.

  1. You are controlling the main character. You choose to control its shadow instead.
  2. That uses one available switch. If you had 2 left, you now have 1.
  3. You reach a gold item and collect it. You get one switch back, so you can take control of the shadow again later.

My contribution: the item restores one used switch, only when the player touches it, and never above the limit of four.

What to watch below: the blue block is the player and the gold block is the restoring item. Watch the counter change 2 → 1 → 2. This small example shows the counting and collection rules; the shadow itself is not shown.

Watch the counter go from 2 → 1 → 2 as one use of the shadow ability is spent and restored. No controls needed.

What my code handles: remembering how many uses remain, checking contact with the item, and preventing the count from going above four.

Shadow ability: 2 / 4 uses left

Move right to reach the gold item.

Keyboard: A/D or arrow keys move; E restores one use while touching the gold item; C restores all four for testing. At 4/4, nothing more can be restored. Simulate using one first to see the counter change.

About this demonstration: This is a standalone browser adaptation using simple shapes; it demonstrates movement and character-switch limits, not character switching or the full game. Implementation references: VerticalMovingPlatform.cs, ExtraSwapItem.cs and CheatCode.cs. The original scripts run in PainterEngine; this page adapts their movement and resource rules to JavaScript.
